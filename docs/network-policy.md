# Сетевой режим IDE

Кнопка **Сетевые настройки** на верхней панели переключает режимы:

- **Обычный**: загрузки приложения разрешены. Автоматические проверки выполняются по отдельным настройкам updater и JDBC-каталога.
- **Только БД**: запрещены startup/периодические и ручные проверки обновлений, загрузка установщиков и blockmap, обращения к JDBC-каталогу, Maven Central, манифестам и файлам сторонних источников драйверов. Уже начатые запросы и чтение ответов прерываются; частичные файлы удаляются штатной обработкой ошибок.

В режиме «Только БД» работают существующие и новые соединения с БД/SSH, метаданные, SQL и локальные файлы. Доступны встроенные/установленные JDBC-драйверы, выбор их версии и импорт локального комплекта JAR. Если нужный драйвер отсутствует, потребуется локальный импорт или явное разрешение загрузок. Настройки обновлений можно сохранить без проверки; удаление токена и стороннего источника также не требует сети.

Полностью загруженное в текущем запуске обновление можно установить: перед установкой updater повторно проверяет размер и SHA256. Смена сетевого режима не отменяет уже начатую установку. После перезапуска приложения updater, как и раньше, заново определяет доступную версию; кэш установщика сам по себе не считается разрешением на установку.

## Сохранение и ошибки

Настройка хранится отдельно в `network-settings.json` внутри каталога данных пользователя:

```json
{ "format": 1, "mode": "database-only" }
```

Она читается до инициализации updater и DriverManager. Для существующих установок без файла сохраняется прежний обычный режим. Чтобы первый запуск в изолированной среде сразу запрещал загрузки, подготовьте этот файл в каталоге данных до запуска приложения. Неизвестный формат, повреждённый или нечитаемый файл оставляет загрузки заблокированными и показывает ошибку; исходный файл не перезаписывается до явного сохранения.

Включение запрета останавливает сеть до записи настройки. Разрешение загрузок вступает в силу только после успешной атомарной записи файла. Ошибка записи оставляет текущий процесс в режиме запрета с предупреждением: сохранение после перезапуска в этом случае не гарантировано.

Отдельные предпочтения автоматических проверок сохраняются. После возвращения обычного режима проверки возобновляются по расписанию либо вручную. Прерванная операция, включая redirects, повтор без истёкшего токена и fallback с дельты на полный файл, не получает нового разрешения при быстром переключении обратно; для неё сохраняется отменённый контекст.

## Границы режима и proxy

Это политика **загрузок IDE**, а не firewall процесса JVM или ОС. Она не ограничивает самостоятельные обращения сторонних JDBC JAR, сетевую аутентификацию, discovery/failover, Before connection tasks и локальные программы, выбранные пользователем. Для строгого egress allowlist нужны отдельные ограничения транспорта/ОС; этот пункт roadmap ещё не выполнен. Включение режима не разрывает транзакции и соединения БД.

Загрузки IDE используют Chromium/Electron и системный proxy/PAC с проверкой TLS. Соединения Node/JDBC идут по собственным настройкам драйвера и SSH; системный proxy updater автоматически на них не переносится. Это описание маршрутов настройки, а не результат диагностики конкретного корпоративного подключения.

Блокировка действует в main process перед общим транспортом, включая прямой вызов IPC. Renderer не определяет разрешение: его кнопки только показывают состояние. CSP продолжает запрещать произвольные сетевые обращения из renderer. Прерывание HTTP обрабатывает [Electron ClientRequest.abort](https://www.electronjs.org/docs/latest/api/client-request#requestabort); обработчик отмены сохраняется до завершения/закрытия ответа, а событие `aborted` завершает чтение с ошибкой. Ранний `close` writable-части запроса не снимает этот обработчик. Контекст операции сохраняется через [AsyncLocalStorage](https://nodejs.org/api/async_context.html#class-asynclocalstorage).

## Проверки

`tests/network-policy.test.ts` проверяет миграцию, сохранение, ошибочные настройки и IPC-значения, отказ записи, конкурирующие изменения режима, отмену ответа/старых retries, startup и двухчасовой период таймеров, локальный JAR и удаление частичной загрузки. На платформах поставки проверяет также offline-установку уже загруженного файла и отказ после его подмены.

`tests/network-policy-desktop.mjs` проверяет настоящий Electron, локальный HTTPS-сервер через CONNECT proxy, сторонний feed, прекращение передачи после первого байта, отсутствие сетевых запросов на старте/после перезапуска/при повреждённых настройках, UI и IPC, импорт настоящего JDBC JAR, JDBC SQLite и сетевой Node/Trino query. Все адреса и профили принадлежат одноразовым fixtures; корпоративные БД и рабочий Keychain не используются. Тест включён в release pipeline macOS ARM64 и Windows x64. Отчёт: `network-policy-results.json`.
