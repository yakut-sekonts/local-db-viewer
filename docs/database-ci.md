# Проверки живых СУБД в CI

Push и pull request запускают `.github/workflows/ci.yml`. Релиз вызывает те же reusable workflows и не публикуется, если интеграции не прошли.

- PostgreSQL 14/18 и SQL Server 2019/2022: `.github/workflows/ddl-catalog.yml`. Проверяются DDL export → restore → export, определения объектов, JDBC-сессии, транзакции, SQL-скрипты и JOIN-подсказки PostgreSQL.
- MySQL 8.4 и MariaDB 10.11/11.4: `.github/workflows/mysql-servers.yml`, `tests/mysql-servers.ts`. Официальные Docker-образы закреплены по manifest digest; точная версия работающего сервера и драйвера записывается в отчёт.

Новый тест использует настоящие `DatabaseSession`, `JdbcWorker`, Java bridge и встроенные JDBC JAR из `runtime-lock.json`. Независимое соединение `mysql2` подготавливает контрольные данные и наблюдает запросы на сервере; пользовательские операции выполняет JDBC.

## Что проверяется

- Успешная аутентификация и сообщение об ошибочном пароле без его раскрытия.
- Unicode в данных и именах таблиц, emoji, LONGTEXT/BLOB, BIGINT/DECIMAL без потери точности, DATETIME(6), NULL, пустые значения и повторяющиеся названия колонок.
- Catalog/table/column metadata и исполняемый preview. Имена с `%` и `_` должны возвращать только выбранную таблицу, а не совпадения wildcard.
- Составной foreign key → SQL-подсказка JOIN → успешное выполнение полученного запроса. Отдельно проверяется `alias.column`.
- BEGIN/COMMIT, SAVEPOINT/ROLLBACK TO, ручной autocommit и rollback при закрытии сессии.
- Остановка скрипта при SQL-ошибке с возможностью явно выполнить ROLLBACK.
- Query timeout и отмена запроса, который уже наблюдается на сервере, с последующим успешным запросом.
- Разрыв живого соединения сервером во время запроса. Незавершённая запись должна откатиться; после явного переподключения запрос работает. Автоматическое воспроизведение SQL не допускается.
- Чтение 60 000 строк LONGTEXT по 2048 символов при heap 48 MiB и сохранении одной строки результата; последующий запрос в той же сессии.
- Отказ при текстовой ячейке больше 4 MiB с сохранением работоспособности следующего запроса.

## Найденные регрессии

Первый прогон выявил две проблемы в 0.18.0: MySQL Connector/J оставлял streaming result активным после query timeout, а MariaDB Connector/J материализовал весь результат до чтения первой строки. Проверки сохранены как обязательные регрессионные сценарии.

В 0.18.1 для MariaDB задаётся `Statement.setFetchSize(1)`; отрицательное значение MySQL для него не применяется. По [документации MariaDB Connector/J](https://mariadb.com/docs/connectors/mariadb-connector-j/about-mariadb-connector-j#streaming-result-sets), положительный fetch size включает ограниченное чтение, тогда как по умолчанию результат читается целиком. MySQL сохраняет собственный режим `Integer.MIN_VALUE`, описанный в [документации Connector/J](https://dev.mysql.com/doc/connector-j/en/connector-j-reference-implementation-notes.html).

После query timeout или отмены MySQL физическое соединение закрывается: драйвер может бросить исключение до привязки streaming result к Statement, и одного `Statement.close()` недостаточно. IDE сбрасывает признак транзакции и показывает предупреждение об откате. Следующий SQL открывает новое соединение с настройками профиля; временные таблицы и session variables прежнего соединения не сохраняются. Прерванный SQL не воспроизводится. Обычные SQL-ошибки не приводят к такому сбросу, поэтому ROLLBACK остаётся доступным для незавершённого скрипта.

## Среда и воспроизводимость

Сервисы работают только на одноразовых Ubuntu CI runners. Тест жёстко использует loopback, схему `ldv_fixture` и фиктивные credentials; переменных для адреса корпоративного сервера или его пароля нет. Нужны `CI=true`, явный флаг `LDV_MYSQL_SERVER_TEST=1`, порт сервиса и `JAVA_HOME`. Root используется только entrypoint контейнера для подготовки тестовой БД; SQL-тесты работают от `ldv_fixture`.

Java получает `-Dstdout.encoding=windows-1252`: проверяется, что JSON-протокол явно использует UTF-8. Это воспроизведение условия кодировки, а не запуск живых MySQL/MariaDB на Windows. Упакованное приложение, JDBC runtime, Fuses, установка и обновление отдельно проверяются на настоящих Windows x64 и macOS ARM64 runners.

`mysql-server-results.json` сохраняется в artifacts `jdbc-mysql-8.4`, `jdbc-mariadb-10.11` и `jdbc-mariadb-11.4`, включая завершённые проверки и ошибку при падении. Обновление digest образов требует повторного прогона всех трёх вариантов. Локальная установка Docker для обычной сборки IDE не нужна.
