# Источники обновлений сторонних JDBC-драйверов

В окне **JDBC-драйверы → нужный драйвер → Источник обновлений** укажите HTTPS URL JSON-манифеста и полный Driver class. Кнопка **Сохранить и проверить источник** читает описание; установка выполняется отдельной кнопкой. Источник действует для конкретного драйвера на этом устройстве и имеет приоритет над встроенным каталогом Maven Central. Для Universal JDBC используется ID `custom`; Driver class также нужно указать в Advanced подключения.

IDE проверяет источник при запуске и каждый час вместе с остальными драйверами. Новый комплект даёт уведомление, в том числе после ручного импорта JAR. Можно проверить версии вручную. При отключённой общей автопроверке фоновых обращений нет. Установка не требует администратора: файлы попадают в каталог пользователя. Открытые JDBC-сессии используют прежнюю версию; новые получают выбранную версию, если профиль не закреплён на другой.

## Публикация комплекта

1. Подготовьте JAR драйвера и все его runtime-зависимости. Порядок аргументов задаёт порядок classpath. IDE не разрешает Maven POM для внешнего источника.
2. Создайте манифест командой ниже. Генератор проверит файлы и вычислит размеры/SHA256. Он не загружает файлы в сеть и не перезаписывает существующий JSON.
3. Разместите JAR по полученным URL, затем опубликуйте JSON по постоянному адресу. Подойдёт HTTPS-сервер вашей команды или публичный GitHub: JSON в ветке через `raw.githubusercontent.com`, JAR в versioned Release assets. Для каждого нового комплекта увеличивайте `revision`. Не заменяйте JAR предыдущей версии.
4. Укажите постоянный URL JSON в IDE. Для следующего выпуска достаточно обновить этот файл; новая версия IDE не нужна.

```sh
node scripts/create-driver-feed.mjs \
  --driver custom \
  --class com.vendor.jdbc.Driver \
  --version 1.2.0 \
  --revision 2 \
  --base-url https://updates.example.org/jdbc/1.2.0/ \
  --output driver-1.2.0.json \
  driver-1.2.0.jar dependency.jar
```

Для встроенных определений `--class` можно опустить, если используется класс из `drivers/definitions.json`. Список поддерживаемых ID находится в этом же файле. Сторонний поставщик может использовать другой класс: укажите его явно и в источнике, и в Advanced подключения.

## Формат JSON

```json
{
  "format": 1,
  "driverId": "custom",
  "driverClass": "com.vendor.jdbc.Driver",
  "revision": 2,
  "version": "1.2.0",
  "files": [
    {
      "url": "https://updates.example.org/jdbc/1.2.0/driver-1.2.0.jar",
      "size": 12345,
      "sha256": "<фактический SHA256: 64 строчных hex-символа>"
    }
  ]
}
```

`revision` — положительное безопасное целое число, строго возрастающее при любом изменении комплекта. `version` — отображаемое имя версии (до 100 символов); допускаются корпоративные обозначения. `driverId` и `driverClass` должны совпадать с настройками источника. Для одной `revision` неизменны версия, класс, URL, порядок и содержимое всех файлов. Ответ с меньшей revision или изменённой существующей revision отклоняется; последняя корректная запись сохраняется.

При первом подключении источника он считается выбранной пользователем линией версий. Импортированный комплект может получить предложение установки даже при совпадающем названии версии: IDE не приравнивает произвольный импорт к проверенному манифесту. Возврат к прежней версии делается выбором установленной версии, а не уменьшением revision на сервере.

## Проверки и ограничения

- Перед активацией проверяются размер и SHA256 каждого JAR, затем загрузка указанного класса настоящей JVM. Проверка класса не устанавливает соединение с БД и не гарантирует совместимость со всеми серверами. Ошибка сохраняет прежний выбранный комплект.
- Манифест ограничен 1 MiB, комплект — 250 файлами / 1 GiB, один JAR — 512 MiB. Размеры проверяются во время загрузки. До трёх внешних источников проверяются одновременно; недоступный источник не мешает остальным.
- Поддерживается HTTPS без авторизации. URL манифеста и JAR не должны содержать пароль, query-параметры или fragment. Допускаются до пяти HTTPS-перенаправлений, включая временные подписанные URL CDN. Они не сохраняются. GitHub-токен обновлений IDE, cookies и пароли подключений не отправляются внешнему источнику. Private GitHub assets и серверы с собственной token-аутентификацией пока не поддерживаются.
- Используются системные proxy/PAC и проверка TLS; передача session credentials отключена через [`ClientRequest.credentials: omit`](https://www.electronjs.org/docs/latest/api/client-request). Выбирайте доверенного поставщика: манифест задаёт исполняемые JAR. SHA256 проверяет соответствие опубликованному комплекту; отдельной цифровой подписи манифеста нет. Распространяйте сторонние файлы только на условиях их лицензии.
- Старая версия остаётся для отката; закреплённая версия профиля и вручную заданный Advanced classpath имеют приоритет. Удаление источника сохраняет установленные файлы и активный выбор. Для импортированной или внешней версии IDE не предлагает автоматическую замену комплектом Maven Central.
- Без источника версий производителя/вашей команды определить новую версию стороннего JAR невозможно; повторный ручной импорт остаётся доступен. По одному внешнему источнику на ID драйвера, в том числе `custom`.

Настройки и последняя корректная версия сохраняются в `drivers/settings.json` каталога пользователя; ошибки сети не удаляют их. Обновление не скачивается и не устанавливается автоматически — пользователь выбирает установку из уведомления.
