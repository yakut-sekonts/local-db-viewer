# Дельта-загрузка обновлений

Начиная с 0.17.0, обновлятор использует ранее загруженный установщик как источник совпадающих блоков. Для Windows это NSIS `.exe`, для macOS — `.zip`. Обычные установочные DMG/EXE остаются полными, содержат Java и встроенные JDBC-драйверы и подходят для установки без предварительного кэша.

## Алгоритм и проверка целостности

1. GitHub release содержит установщик и его gzip blockmap v2 с SHA256. Публикация требует обе карты; они входят в `SHA256SUMS.txt`.
2. Проверяются размер и SHA256 карты, ограничивается размер её распаковки. Принимается только карта одного файла с непрерывным покрытием всего установщика.
3. Предыдущая загрузка проверяется по полному SHA256. Карта выбирает блоки для копирования; её короткие block checksums не заменяют проверку целого файла.
4. Изменившиеся диапазоны загружаются через HTTPS с `Range`. Соседние диапазоны объединяются: не более 64 запросов, не более двух минут на восстановление. Если пришлось бы получить 90% файла или больше, выбирается полная загрузка.
5. Ответ должен иметь HTTP 206 и точный `Content-Range`; проверяются длина и отсутствие транспортного сжатия. Signed URL используется только в памяти; токен передаётся исключительно GitHub API. Сохраняются системный proxy/PAC и проверка TLS.
6. Восстановленный файл проходит проверку размера и SHA256 и атомарно переименовывается из `.part`. Перед передачей обычному установщику SHA256 проверяется повторно. Установленная копия приложения во время загрузки не изменяется.

При повреждении кэша, карты, Range-ответа или восстановленного файла обновлятор удаляет частичный файл и переходит на полную загрузку с независимой проверкой SHA256. Ошибка полной загрузки останавливает обновление. Сбой не переключает установленную версию и не позволяет установить частичный файл.

## Первый переход и кэш

Переход на 0.17.0 со старого обновлятора выполняется полностью. В дальнейшем можно использовать сохранённый установщик 0.17.0: обновлятор найдёт его в своей папке загрузок, получит карту из релиза этой конкретной версии и проверит хеши. Он не скачивает старый установщик только ради создания базы.

После ручной установки или удаления кэша следующая загрузка будет полной. После неё `updates/delta-cache.json` указывает на новую проверенную базу. Запись содержит только относительное UUID-имя папки и описание release assets; токены и signed URL в неё не записываются. Изменение GitHub-репозитория требует проверки базы по новому источнику. Смена Stable/Beta не отменяет проверку релиза и не ослабляет проверку файла.

Кэш занимает место на диске, примерно равное полному установщику, дополнительно к новому файлу во время загрузки. Прежние папки загрузок и журналы установки сохраняются, как в предыдущих версиях; автоматическая очистка истории загрузок в этот выпуск не входит.

## Размер и отображение

Повторно используются фактически совпадающие байты, в том числе сжатые Java и JAR. Одинаковый `runtime-lock.json` сам по себе не гарантирует одинакового архива: имеют значение формат сжатия, порядок файлов, метаданные и подпись. Поэтому lock-файл не используется как разрешение пропустить проверку или заменить runtime.

Интерфейс показывает полученные MiB, включая карты и прочитанные байты неудачной попытки дельта-загрузки, и повторно используемые MiB итогового установщика. Прогресс относится к сборке файла и при переходе к полной загрузке начинается заново. В счётчик не включены HTTP-заголовки и JSON метаданных GitHub. Экономия не гарантируется для каждой пары версий.

Поддержка blockmap в сборщике: [electron-builder NSIS](https://www.electron.build/nsis/). Windows использует differential-aware упаковку, macOS — внешнюю карту ZIP. После загрузки используются существующие механизмы установки и перезапуска; резервная копия macOS сохраняется, Windows rollback остаётся отдельной задачей.
