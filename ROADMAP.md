# План Local DB Viewer

Согласованный порядок от 2026-09-30. Статусы ниже относятся к реализации и проверкам, а не к юридической сертификации продукта.

## P0 — распространение и надёжность

1. **Лицензирование — выпущено в 0.16.0, release CI пройден.** Apache-2.0 для исходников; оригинальные LICENSE/NOTICE для JDBC, их embedded/shaded-зависимостей, npm и Electron. Сохранён Java `legal`, добавлен просмотр лицензий без сети. Закреплённые исходники Java/MySQL/MariaDB/Trino и приложения публикуются рядом с установщиками. Проверяются хеши, полнота реестра, чистый Git-архив и упакованные ресурсы. Эти проверки не заменяют юридическую оценку новых зависимостей.
2. **CI на push/PR и beta-канал — выпущено в 0.16.0, release CI пройден.** Сборка и unit-тесты Linux/Windows, живые PostgreSQL/SQL Server, read-only permissions. Stable по умолчанию, явный выбор Beta, числовое сравнение `X.Y.Z-beta.N`, переход beta → stable без автоматического downgrade. Публикация beta не меняет latest. Проверены интерфейс и реальная установка Stable/Beta на обеих платформах с сохранением профиля и SQL; Windows также подтверждает перезапуск в том же пути с кириллицей. [Релиз](https://github.com/yakut-sekonts/local-db-viewer/releases/tag/v0.16.0), [успешный release pipeline](https://github.com/yakut-sekonts/local-db-viewer/actions/runs/36832795892).
3. **Подпись установщиков — нужна инфраструктура владельца.** На 2026-10-01 владелец подтвердил, что Apple Developer и сертификата/сервиса подписи Windows пока нет. Нужны Developer ID и notarization для macOS; сертификат/сервис подписи Windows. Подготовить проверки подписей в сборке и updater. Покупка, enrolment и секреты аккаунтов не входят в автоматические изменения репозитория; ключи не передаются в чат. Цены и доступность проверяются перед подключением сервиса. До появления этой инфраструктуры следующий технический пункт — connection timeout; текущая ad-hoc подпись macOS не считается выполнением этого пункта.
4. **Connection timeout — выпущено в 0.16.1, release CI пройден.** Свойства известных драйверов с правильными единицами, Advanced/URL priority, отдельный общий лимит открытия JDBC-сессии, `0` без скрытого fallback, отмена и повторное подключение. Trino/ClickHouse проверяют сеть через SELECT 1. Длительный SQL после подключения не затрагивается; metadata timeout приостанавливается на время открытия. На macOS ARM64 и Windows x64 проверены молчащий TCP-сервер для шести драйверов, неотзывчивый драйвер, ожидание более 30 секунд при `0`, запоздалые сообщения старой JVM, приоритет URL SQL Server и desktop IPC. Также прошли реальные установки тестовых обновлений Stable/Beta с сохранением профиля и SQL; Windows подтверждает перезапуск в том же пути с кириллицей. [Релиз](https://github.com/yakut-sekonts/local-db-viewer/releases/tag/v0.16.1), [успешный release pipeline](https://github.com/yakut-sekonts/local-db-viewer/actions/runs/36867533863). Семантика и границы — в [документации](docs/connection-timeouts.md).

## P1

5. **Дельта-обновления.** Разделить приложение и неизменившийся runtime по хешам; сохранить проверку целостности, полную установку как fallback и восстановление после сбоя. Один `runtime-lock.json` ещё не обеспечивает безопасный патчер установленного приложения.
6. **Electron Fuses.** Выключить RunAsNode/NodeOptions/inspect, включить совместимые проверки ASAR. Проверить влияние на JDBC/Node workers, упаковку, подпись, updater и тестовый запуск Electron.
7. **Живые СУБД в CI.** PostgreSQL 14/18 и SQL Server 2019/2022 уже проверяются в release pipeline. Добавить MySQL/MariaDB, сетевые ошибки и Unicode; расширить запуск до push/PR.
8. **Сетевые настройки.** Отдельные задачи ниже. Не называть продукт compliance-ready без определённых требований и проверок.

## P2

9. **JRE по требованию.** Малый установщик, проверяемая загрузка Java, offline-дистрибутив и понятное поведение без доступа к сети.
10. **Диагностика.** Кнопка копирования версии/ОС/состояния updater с удалением секретов, персональных путей, SQL и чувствительных адресов; отправка пользователем вручную.
11. **Проверка зависимостей.** OSV/npm audit; PR на обновление Java/JAR с хешами, лицензиями и тестами. Автоматическая проверка каталога JDBC уже существует; встроенная Java остаётся закреплённой.
12. **Windows rollback.** Резервная копия и восстановление при неудачном обновлении/запуске, тесты частичной установки и занятых файлов. macOS уже сохраняет предыдущую копию.
13. **SQL Server Integrated Authentication.** Правильная x64-библиотека для каждой версии драйвера, её лицензия, безопасная загрузка и проверка на Windows.

## P3

14. **Локализация и документация.** EN README/интерфейс/ошибки, счётчики из definitions.json, явная конфигурация upstream.
15. **Гигиена desktop.** Single-instance lock с учётом updater и изолированных тестов, resourceLimits Node workers, ограничения DevTools в поставке. Java уже запускается с `-Xmx512m`.
16. **Миграция legacy-подключений на JDBC.** Проверяемая миграция с сохранением настроек и откатом, после неё удаление Node-драйверов и соответствующих зависимостей.

## Сетевой трек

- SPKI pin для TLS: проверка реально используемого транспорта, ротация pin и ясное взаимодействие с CA/hostname verification; отдельная поддержка native и JDBC.
- Корпоративный CA: явные режимы «только этот CA» и «системные корни + этот CA». Имена CA/FULL/NONE разных JDBC-драйверов нельзя переопределять одним универсальным переключателем.
- Offline/egress: запрет фоновых и ручных внешних загрузок в рамках выбранной политики, включая startup checks и JDBC-каталог. Соединения БД/SSH оговорить отдельно. Одного отключения двух таймеров недостаточно.
- Proxy: показывать фактический маршрут соединения; системный proxy обновлений не распространяется автоматически на JDBC/Node-драйверы.
- Allowlist профиля: учесть DNS, redirects, discovery, failover и SSH. Проверка исходного host:port сама по себе не ограничивает весь egress JVM.
- SSH tunnel: проверить привязку назначения и защиту локального listener; ограничения должны работать для каждого поддерживаемого JDBC transport.

## Функции после P0

- Локальная блокировка хранилища: модель защиты и KDF/лимиты попыток; UI PIN поверх открытых секретов не является шифрованием хранилища.
- Экспорт/импорт профилей без секретов: проверка схемы, VM options, путей JAR, startup/before-connect команд; сохранение не должно запускать импортированную конфигурацию.
- Локальный audit log: явное включение, ротация/лимиты/права файлов и выбор состава данных; без телеметрии. Локальный файл сам по себе не является защищённым от подмены аудитом.
- История: поиск и восстановление контекста выпущены в 0.15.0. Следующее — параметры с типами и безопасным связыванием, без текстовой подстановки SQL.
- Read-only: гарантии прав обеспечивать ролью/учётной записью на стороне БД; `setReadOnly`, startup script и анализ SQL сами по себе универсальной гарантии не дают.
- Общая конфигурация workspace: отделить переносимые настройки от секретов и исполняемой локальной конфигурации; изменения применять явно.
